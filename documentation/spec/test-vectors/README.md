# obie/0.1 signing test vectors

Each `*.json` file is one test vector for signing and verifying obie/0.1
events. An independent implementation should reproduce every field from the
event and the key alone.

## Signing rules

1. Take the event as JSON and remove `publisher.signature`.
2. Canonicalize the result with the JSON Canonicalization Scheme,
   [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785). Strings must be valid
   UTF-8; integers must lie within ±(2^53−1) (I-JSON).
3. Sign the canonical bytes with Ed25519 ([RFC 8032](https://www.rfc-editor.org/rfc/rfc8032)).
4. Set `publisher.signature` to `ed25519:` followed by the 64-byte signature
   in unpadded base64url ([RFC 4648 §5](https://www.rfc-editor.org/rfc/rfc4648#section-5)).

`publisher.peer_id` is the libp2p peer ID of the signing key in base58btc
form: the identity multihash (`0x00 0x24`) of the protobuf public key
`0x08 0x01 0x12 0x20 <32-byte key>`. A verifier extracts the public key from
the peer ID; no key lookup is needed.

Signature verification is independent of field validation. A receiver both
validates the event against the obie/0.1 rules and verifies its signature.

## File format

| Field              | Meaning                                                                                      |
|--------------------|----------------------------------------------------------------------------------------------|
| `name`             | File name without `.json`.                                                                   |
| `description`      | What the vector exercises.                                                                   |
| `private_key_seed` | Hex 32-byte Ed25519 seed of the key that made the signature. **Public, test use only.**      |
| `public_key`       | Hex public key of that seed.                                                                 |
| `event`            | The event as a receiver gets it, signature included.                                         |
| `canonical`        | Hex of the RFC 8785 form of `event` without `publisher.signature`.                          |
| `signature`        | `event.publisher.signature`.                                                                 |
| `protocol_valid`   | Whether `event` satisfies every obie/0.1 field rule at its `issued_at`.                      |
| `valid`            | Whether the signature verifies against the key in `event.publisher.peer_id`.                |

For valid vectors, signing `canonical` with `private_key_seed` reproduces
`signature` (Ed25519 is deterministic). Negative vectors (`valid: false`) must
be rejected:

- `06-tampered` changes a field after signing.
- `07-wrong-key` is signed by a key other than the one in the peer ID.

The keys are the RFC 8032 §7.1 test keys 1 (vectors 01, 03–06) and 2
(vectors 02, 07).

## Regenerating

The vectors are generated by `TestVectors` in `pkg/obieproto`, which also
fails when a file is out of date. After an intended change run:

```sh
go generate ./pkg/obieproto
```
